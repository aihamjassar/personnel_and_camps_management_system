# نظام إدارة شؤون الأفراد والمعسكرات

**اللغة:** [English](README.md) · [العربية](README.ar.md)

مشروع أكاديمي متكامل لإدارة سجلات أفراد افتراضيين ومرافق المعسكرات. يستخدم النظام React وTypeScript وExpress وPrisma وPostgreSQL، مع واجهة عربية تدعم اتجاه الكتابة من اليمين إلى اليسار (RTL). **استخدم بيانات افتراضية أكاديمية فقط؛ لا تُدخل بيانات أفراد أو بيانات عسكرية أو معلومات حساسة حقيقية.**

> **حالة المشروع:** اكتمل تنفيذ متطلبات API الموثقة FR-01–FR-16، وأُضيف دليل المستخدم ومرجع API والمرجع الفني ومصفوفة التتبع. آخر قياس: 50/50 اختبارًا ناجحًا وتغطية أسطر/تعليمات 92.58%. لا تُعدّ النسخة منشورة: مراجعة الفريق، اختبار E2E، معالجة تحذيرات الإنتاج، والمضيف/النطاق الفعلي ما زالت مطلوبة. راجع [قائمة Phase 4](docs/Todo-Phase-4.md) و[تقرير الاختبارات](docs/Testing-Report.md).

## الميزات

- تسجيل دخول بجلسة، ومصادقة JWT، وتحكم بالصلاحيات حسب الدور على مستوى API (RBAC).
- واجهة عربية RTL ولوحة ملخصات.
- إدارة الأفراد مع سجل تراكمي غير قابل للاستبدال لتغييرات الحالة، وحذف منطقي.
- إدارة المعسكرات والوحدات التنظيمية والرتب والمناصب والتعيينات.
- انتقالات بين المعسكرات تتحقق من وحدة الوجهة والسعة؛ تُحفظ بيانات الفرد والانتقال والتدقيق ذريًا ضمن معاملة واحدة.
- إدارة المستخدمين والأدوار والصلاحيات، مع تطبيق تغييرات الصلاحيات ديناميكيًا.
- سجل تدقيق قابل للفلترة، وتصدير تقارير PDF/Excel، وإشعارات داخلية، وبحث مركّب عن الأفراد.

## التقنيات

- **الواجهة:** React 18 وTypeScript وVite وTailwind CSS وأيقونات Lucide.
- **الخادم:** Node.js وExpress وTypeScript وZod.
- **البيانات:** PostgreSQL وPrisma ORM.
- **الاختبارات:** Vitest وSupertest على قاعدة PostgreSQL مخصصة للاختبارات.

## المتطلبات

- Node.js الإصدار 20 أو أحدث وnpm.
- خادم PostgreSQL محلي للتطوير واختبارات التكامل.

## الإعداد المحلي

نفّذ الأوامر من جذر المستودع ما لم يُذكر غير ذلك.

1. ثبّت الاعتمادات:

   ```bash
   npm ci
   ```

2. أنشئ قاعدة بيانات التطوير وملف إعداد الخادم المحلي:

   ```bash
   createdb personnel_camps
   cp server/.env.example server/.env
   cp client/.env.example client/.env
   ```

   عدّل `server/.env` واضبط `DATABASE_URL` ليتوافق مع اتصال PostgreSQL لديك، واستبدل `JWT_SECRET` بقيمة سرية قوية. يستخدم العميل المسار النسبي `/api/v1` افتراضيًا؛ يمرره Vite إلى خادم التطوير. لا ترفع ملفات `.env` إلى Git ولا تشارك الأسرار.

3. طبّق الترحيلات وأضف بيانات عرض افتراضية:

   ```bash
   npm run db:deploy -w server
   npm run db:seed -w server
   ```

   توجد إعدادات Prisma CLI، بما فيها أمر إضافة البيانات، في [`server/prisma.config.ts`](server/prisma.config.ts).

4. شغّل خادم API والواجهة:

   ```bash
   npm run dev
   ```

   - الواجهة: <http://localhost:5173>
   - عنوان API الأساسي: <http://localhost:4000/api/v1>
   - فحص التوافر العام: <http://localhost:4000/api/v1/health>

   يمرر خادم تطوير Vite طلبات `/api` إلى خادم API.

## حساب العرض

بعد إضافة البيانات التجريبية، استخدم `admin` / `Admin@1234` للعرض الأكاديمي المحلي فقط. يجب **تغيير بيانات الدخول هذه أو حذفها قبل أي نشر**. لا تستخدم بيانات دخول حقيقية أو معلومات شخصية حقيقية في العروض.

## الفحوص والبناء

```bash
npm run typecheck
npm test
npm run coverage
npm run build
```

تستخدم اختبارات التكامل قاعدة البيانات المنفصلة `personnel_camps_test`، ويُعاد ضبط مخططها قسرًا عند تشغيل الاختبارات. **لا توجّه إعداد الاختبارات إلى قاعدة تطوير أو إنتاج تحتوي على بيانات تحتاجها.** تُولّد الاختبارات وتقارير التغطية Prisma Client تلقائيًا قبل التشغيل. بيانات الاختبار اصطناعية، والتغطية المحسوبة تخص مصدر الخادم فقط.

## ملاحظات API والصلاحيات

توجد مسارات API ذات الإصدارات تحت `/api/v1`. تتطلب مسارات التطبيق المحمية مصادقة JWT وصلاحية RBAC يتحقق منها الخادم. هناك مساران عامان عن قصد: `POST /api/v1/auth/login` و`GET /api/v1/health` لفحص التوافر فقط. تعيد نقطة الصحة المغلف الأدنى `{ "status": "success", "data": { "ok": true }, "error": null }` ولا تكشف معلومات عن قاعدة البيانات أو تفاصيل تشغيلية.

## تنبيه قبل النشر

قبل أي نشر، اضبط قاعدة PostgreSQL منفصلة وسر JWT خاصًا وقويًا وHTTPS وإعدادات CORS المناسبة للإنتاج. غيّر بيانات التطوير واستخدم بيانات مسموحًا بها للبيئة المستهدفة فقط؛ نطاق المشروع الحالي أكاديمي ويعتمد على بيانات افتراضية.
