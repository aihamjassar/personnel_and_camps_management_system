# تسلسل الأحداث (Flow of Event)

> يركّز هذا الملف على **الأحداث (Events)** التي يُطلقها النظام استجابة لإجراءات المستخدم أو لتغيّرات الحالة الداخلية — بخلاف `Flow-of-Action.md` الذي يركّز على تدفق الطلب عبر الطبقات المعمارية.

---

## 1. مفهوم الحدث في هذا النظام

الحدث (Event) هو أي تغيير حالة مهم يستحق أن يُسجَّل و/أو يُبلَّغ عنه: إنشاء سجل، تعديل حساس، فشل مصادقة، تجاوز حد أمني، أو تغيير حالة فرد.

---

## 2. جدول الأحداث الرئيسية

| الحدث | المُطلِق | الاستجابة التلقائية للنظام |
|---|---|---|
| `PersonnelCreated` | إنشاء فرد جديد (FR-01) | تسجيل في `AuditLogs` |
| `PersonnelUpdated` | تعديل بيانات فرد (FR-02) | تسجيل القيم القديمة/الجديدة في `AuditLogs` |
| `PersonnelStatusChanged` | تغيير حالة فرد (FR-04) | سجل تاريخي جديد في `PersonnelStatus` + إشعار (Should-Have) |
| `TransferRequested` | طلب انتقال (FR-09) | التحقق من السعة → قبول/رفض |
| `TransferCompleted` | نجاح معاملة النقل | تحديث `unit_id` + إشعار لمدير المعسكر المستقبِل |
| `TransferRejected` | فشل التحقق من السعة أو الصلاحية | إشعار لمقدّم الطلب برسالة توضيحية |
| `UserLoginSucceeded` | نجاح تسجيل الدخول | إصدار JWT، تسجيل وقت آخر دخول |
| `UserLoginFailed` | فشل تسجيل الدخول | زيادة عدّاد المحاولات الفاشلة |
| `AccountLockedTemporarily` | تجاوز حد المحاولات (Rate Limiting) | حظر مؤقت + تسجيل في `AuditLogs` |
| `RoleOrPermissionChanged` | تعديل دور/صلاحية (FR-11) | تسجيل فوري في `AuditLogs` (حدث حسّاس) |
| `ReportGenerated` | توليد تقرير (FR-13) | تسجيل نوع التقرير وطالبه |
| `SystemSettingChanged` | تعديل إعداد عام (FR-16) | تسجيل إلزامي في `AuditLogs` (صلاحية مدير النظام فقط) |
| `SessionExpired` | انتهاء صلاحية الجلسة الزمنية | تسجيل خروج تلقائي، إعادة توجيه لصفحة الدخول |

---

## 3. مخطط تسلسل الأحداث — مثال: دورة حياة "طلب انتقال"

```
المستخدم يقدّم الطلب
        │
        ▼
  TransferRequested  ───► يتحقق النظام من سعة المعسكر الهدف
        │
   ┌────┴─────┐
   ▼          ▼
ناجح        فاشل
   │          │
   ▼          ▼
TransferCompleted   TransferRejected
   │                    │
   ▼                    ▼
إشعار للمدير المستقبِل   إشعار لمقدّم الطلب
   │                    │
   ▼                    ▼
تسجيل AuditLogs      تسجيل AuditLogs (محاولة مرفوضة)
```

---

## 4. الأحداث الأمنية الحرجة (يجب تسجيلها دون استثناء)

بحسب قسم "تحليل الأمان" في دراسة الجدوى، الأحداث التالية **إلزامية التسجيل**:

1. كل محاولة تسجيل دخول (ناجحة أو فاشلة) مع الطابع الزمني وهوية الجهاز/IP.
2. كل تعديل أو حذف لبيانات الأفراد أو المعسكرات.
3. كل تغيير في الأدوار أو الصلاحيات.
4. كل استعراض لسجلات التدقيق نفسها (Meta-Audit).
5. كل عملية استعادة من نسخة احتياطية.
6. انتهاء الجلسة تلقائيًا بعد فترة خمول محددة.

---

## 5. آلية الإشعارات المرتبطة بالأحداث (FR-15)

| الحدث | من يستلم الإشعار |
|---|---|
| `TransferRequested` | مدير المعسكر المستقبِل |
| `PersonnelStatusChanged` (لحالة حسّاسة كـ "منتهي الخدمة") | ضابط شؤون الأفراد + مدير الوحدة |
| `RoleOrPermissionChanged` | مدير النظام (نسخة إشعار تأكيدية) |
| `AccountLockedTemporarily` | صاحب الحساب + مدير النظام |

---

## 6. مبدأ عزل الأحداث عن منطق العرض

الأحداث تُطلَق من **طبقة منطق الأعمال (Business Logic Layer)** ويلتقطها **Integration Layer** لتوزيعها (تسجيل تدقيقي، إشعار، أو كليهما)، دون أن تعرف طبقة العرض (Frontend) أي تفاصيل داخلية — تستقبل فقط النتيجة النهائية بصيغة `{status, data, error}`.
