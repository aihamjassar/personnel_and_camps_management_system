# المرجع الفني للنظام

**المشروع:** نظام إدارة شؤون الأفراد والمعسكرات — إصدار توثيق Phase 4، 2026-10-05
**النطاق:** تطبيق أكاديمي ببيانات اصطناعية فقط. لا يُعتمد لإدارة أفراد حقيقيين أو معلومات تشغيلية/عسكرية.

## 1. النظرة المعمارية

تطبيق ويب بطراز **Modular Monolith** وواجهات REST JSON: واجهة React SPA تتصل بخادم Express، ويستخدم الخادم Prisma للوصول إلى PostgreSQL. طبقات التكامل تجمع تحديثات الأعمال التي يلزم حفظها ذريًا، وتصدر سجلات التدقيق والإشعارات من الخادم لا من المتصفح.

| الطبقة | التقنية / المسؤولية |
|---|---|
| واجهة المستخدم | React 18، TypeScript، Vite، Tailwind CSS، Lucide؛ واجهة عربية RTL |
| التوجيه والعرض | React Router؛ مسارات محمية حسب صلاحيات المستخدم المسجلة |
| API | Express 5، JSON، Zod للتحقق من المدخلات، Helmet وCORS |
| منطق الأعمال والتكامل | عمليات الأفراد والتعيينات والانتقالات والأدوار والإشعارات والتدقيق |
| الاستمرارية | Prisma ORM 6 وPostgreSQL 16؛ ترحيلات SQL مُدارة في `server/prisma/migrations/` |
| الاختبار | Vitest وV8 coverage وSupertest، على قاعدة اصطناعية منفصلة |

## 2. وحدات النظام

1. تسجيل الدخول والجلسة والاستعادة.
2. الأفراد: الإنشاء والتعديل والبحث والترشيح وتاريخ الحالة والحذف المنطقي.
3. المعسكرات وسعتها ووحداتها التنظيمية.
4. الرتب والمناصب والتعيينات.
5. الانتقالات بين المعسكرات والتحقق من سعة الوجهة واتساق الوحدة.
6. المستخدمون والأدوار والصلاحيات (RBAC ديناميكي).
7. لوحة المعلومات والتقارير والتصدير إلى PDF/Excel.
8. سجل تدقيق قابل للترشيح وغير قابل للتعديل عبر API.
9. إشعارات داخل التطبيق.
10. إعدادات النظام FR-16: قواعد كلمة المرور ومدة JWT.

راجع [مرجع API](API-Reference.md) و[دليل المستخدم](User-Guide.ar.md) لفهرس نقاط الدخول وخطوات كل دور.

## 3. إعداد بيئة التطوير

المتطلبات: Node.js 20+، npm، PostgreSQL. نفّذ من جذر المستودع:

```bash
npm ci
createdb personnel_camps
cp server/.env.example server/.env
cp client/.env.example client/.env
```

اضبط `DATABASE_URL` و`JWT_SECRET` و`CLIENT_ORIGIN` في `server/.env`، ثم:

```bash
npm run db:deploy -w server
npm run db:seed -w server
npm run dev
```

واجهة التطوير على `http://localhost:5173` وAPI على `http://localhost:4000/api/v1`. يستخدم العميل `/api/v1` من الأصل نفسه افتراضيًا ليمر عبر Vite proxy محليًا وCaddy في حزمة العرض. حساب `admin / Admin@1234` خاص بالتطوير المحلي الأكاديمي فقط.

### متغيرات البيئة الأساسية

- `DATABASE_URL`: اتصال PostgreSQL الخاص بالبيئة.
- `PORT`: منفذ الخادم (4000 محليًا).
- `JWT_SECRET`: سر خاص قوي لتوقيع JWT؛ يجب تغييره لكل بيئة.
- `JWT_EXPIRES_IN`: قيمة رجوع لمدة الجلسة عند عدم وجود إعداد محفوظ؛ إعداد FR-16 المحفوظ هو المرجع الأعلى. القيم غير المعتادة تُحصر في 1–24 ساعة.
- `CLIENT_ORIGIN`: أصل العميل المسموح في CORS.
- `BOOTSTRAP_ADMIN_PASSWORD`: لا يُستخدم إلا لتهيئة أول مدير في بيئة الإنتاج، ويُمرر مؤقتًا لخدمة bootstrap فقط. لا يُسجّل في المخرجات؛ لا تُضمّنه في الصورة أو Git.

## 4. قاعدة البيانات والترحيلات

يحتوي مخطط Prisma على **14 جدولًا وظيفيًا** وجدولي الربط `user_roles` و`role_permissions`. تشمل الأجزاء الحساسة تاريخ حالة الفرد، الانتقالات، سجل التدقيق، الإشعارات، وإعدادات النظام.

```bash
npm run db:generate -w server
npm run db:deploy -w server       # يطبّق الترحيـلات المسجلة
npm run db:seed -w server         # بيانات عرض أكاديمية
```

ترحيل إعدادات النظام: `server/prisma/migrations/20261003140000_system_settings/`. جرى التحقق من تطبيق سلسلة الترحيلات كاملة على قاعدة PostgreSQL اصطناعية جديدة. لا تشغّل `db:seed` في الإنتاج من دون سرّ `BOOTSTRAP_ADMIN_PASSWORD`؛ النسخة المحلية وحدها تستخدم كلمة مرور التطوير المعروفة.

**قاعدة الاختبار مستقلة وخطرة على بياناتها:** إعداد Vitest يعيد مخطط `personnel_camps_test` قسرًا قبل مجموعة الاختبار. لا توجّه `server/.env` إلى قاعدة تطوير/عرض/إنتاج قبل `npm test` أو `npm run coverage`.

## 5. ضوابط الأعمال والأمان

- JWT للمصادقة؛ يحمل العميل الرمز في `sessionStorage`. يجلب الخادم صلاحيات المستخدم النشطة من PostgreSQL عند كل طلب، فتسري تغييرات الأدوار فورًا.
- RBAC خادمي إلزامي على كل مسار محمي. الاستثناءان العامان: `POST /api/v1/auth/login` وفحص الصحة المحدود `GET /api/v1/health`.
- تحديد محاولات الدخول: 20 طلبًا لكل عنوان IP خلال 15 دقيقة.
- كلمات المرور مجزأة بـbcrypt. FR-16 يسمح بطول 8–64 حرفًا مع قواعد اختيارية للحرف الكبير بحسب فئة Unicode والرقم والرمز؛ تُفرض القواعد عند إنشاء كلمة مرور أو إعادة تعيينها فقط.
- مدة JWT الجديدة قابلة للضبط بين 1 و24 ساعة. تغيير المدة لا يبطل الرموز الصادرة سابقًا.
- `helmet`، CORS بأصل محدد، وحد JSON أقصى 1 MB.
- حذف الفرد منطقي؛ تاريخ الحالة لا يُستبدل.
- النقل وتحديث الفرد والوحدة وسجل التدقيق تُحفظ في معاملة ذرية، مع التحقق من سعة المعسكر ووحدة الوجهة.
- تعديل FR-16 يُحفظ مع `SystemSettingChanged` (القيم السابقة والجديدة وهوية المدير) ضمن معاملة واحدة. لا تُحفظ أسرار الدخول ضمن إعدادات النظام.
- سجل التدقيق للقراءة فقط من خلال API؛ التغيير والحذف ليسا عمليتين متاحتين.

## 6. استراتيجية الاختبار والنتائج

- اختبارات التكامل: Vitest/Supertest على PostgreSQL محلي اصطناعي منفصل.
- اختبارات وحدة مستقلة لمقيّم سياسة كلمة المرور وإعدادات FR-16 ومخططات الطلب الأربعة عشر.
- نتيجة التشغيل بتاريخ 2026-10-05: **50/50 اختبارًا**، منها 29 اختبار API/تكامل و21 اختبار وحدة.
- تقرير التغطية الحالي: **92.58%** للأسطر/التعليمات، **97.22%** للدوال، و**73.25%** للفروع. الحد الآلي في الإعداد 70% للأسطر؛ تجاوزت الفروع 70% في هذا التشغيل، لكنها ليست حدًا مفروضًا.
- اجتاز `npm run typecheck` و`npm run build` بعد تعديل FR-16.
- اختُبرت سلسلة Prisma migrations على قاعدة جديدة، كما أُنشئ تفريغ PostgreSQL اصطناعي مشفّر بـage ثم فُكّ وفُحص بـ`pg_restore`.
- هذه الأدلة ليست بديلًا عن اختبار متصفح شامل أو مراجعة بشرية مستقلة.

التفاصيل القابلة لإعادة التشغيل في [تقرير الاختبارات](Testing-Report.md).

## 7. النشر التجريبي والاستعادة

توجد حزمة Docker Compose قابلة للنقل في [`deploy/staging/README.md`](../deploy/staging/README.md): PostgreSQL، API، Caddy لـHTTPS، تهيئة مدير لمرة واحدة، ونسخ احتياطي يومي مشفّر إلى volume محلي.

**لم تُنشر الحزمة فعليًا:** يلزم مضيف Docker دائم واسم نطاق/DNS مخوّل ومفاتيح TLS وحساب/تخزين نسخ احتياطي خارج الموقع، ولا يُعد Sandbox المؤقت قاعدة إنتاجية. قبل نشر عام يجب معالجة مراجعة الاعتمادات الأمنية؛ أظهر آخر `npm audit` 15 تحذيرًا إجمالًا (8 عالية و7 متوسطة)، و`npm audit --omit=dev` أظهر 7 ضمن شجرة الإنتاج (3 عالية و4 متوسطة). تتطلب الإصلاحات المتاحة خطة توافق وترقيات مُراجعة. تكوين HTTPS في Caddy لا يثبت صدور شهادة قبل توصيل النطاق وفتح المنافذ والتحقق من الوصول من شبكة خارجية.

سجّل دليل النشر فترة الاحتفاظ المحلية (14 يومًا افتراضيًا)، التشفير العام بمفتاح `age`، وخطوات الاستعادة. تبقى نسخة خارج الموقع ومراجعة نجاح الاستعادة مسؤولية مالك المضيف.
