# مصفوفة تتبع المتطلبات والتحقق — Phase 4

**تاريخ المراجعة:** 2026-10-05
**مصادر المراجعة:** حالات الاستخدام، المسارات، المخططات، اختبارات API والوحدات، صفحات React، ملفات النشر. بيانات اصطناعية فقط.

## خلاصة الأدلة والحدود

- اختبارات Vitest الناجحة: **50/50** — 29 اختبار API/تكامل و21 اختبار وحدة في ثلاثة ملفات.
- كل مجموعة وظيفية FR-01 إلى FR-16 لها مسار خادمي واختبار API ذي صلة؛ لكن هذا **لا يثبت قبولًا مرئيًا كاملًا بالمتصفح**.
- لا توجد مجموعة E2E آلية تغطي جميع الأدوار والسيناريوهات. توجد ملاحظات تحقق متصفح يدوية أقدم، ولا تغطي كل التغييرات الحالية.
- لا يوجد مضيف staging دائم أو نطاق DNS موصول؛ كما تظهر 7 تحذيرات في شجرة الاعتمادات الإنتاجية، لذلك لم تُنشر الخدمة.

## المصفوفة

| المتطلب | الشاشة / المسار | دليل التنفيذ والاختبار | الحالة والحدود |
|---|---|---|---|
| **FR-01 إنشاء فرد** | `/app/personnel` | `POST /api/v1/personnel`، وحالة `personnel › creates, lists, updates personnel with the unified envelope` | **API مغطى.** الاسم مطلوب؛ الرتبة والوحدة اختياريتان. يبدأ السجل بحالة `active` ويُكتب سجل الحالة والتدقيق. لا اختبار قبول متصفح شامل. |
| **FR-02 تعديل/حذف فرد** | `/app/personnel` | `PUT/DELETE /api/v1/personnel/:id`؛ اختبار تحديث الفرد والحذف المنطقي | **API مغطى.** الحذف منطقي عبر `deleted_at` لا حذف صف. لم يُختبر تفاعل الواجهة آليًا. |
| **FR-03 البحث المتقدم** | `/app/personnel` | `GET /api/v1/personnel`؛ البحث والمرشحات والترقيم ضمن اختبار قائمة الأفراد | **API مغطى.** البحث والقراءة يتطلبان `personnel.manage`؛ وُحّدت المواصفة لتسمية هذه الصلاحية بدل الإيحاء بأن كل دور مصادق يستطيع قراءة سجلات الأفراد. |
| **FR-04 تاريخ الحالة** | `/app/personnel` | `POST/GET /api/v1/personnel/:id/status`؛ `appends status history without overwriting old rows` | **API مغطى.** كل تغيير يضيف سجلًا تاريخيًا ويحدّث الحالة الحالية؛ لا اختبار E2E للشاشة. |
| **FR-05 المعسكرات والسعة** | `/app/camps` | اختبار CRUD المرجعي، RBAC، وفحوص السعة خلال سيناريو الانتقال | **API مغطى.** CRUD خادميًا؛ واجهة المعسكر لا تعرض حذفًا. السعة تُفرض عند النقل. |
| **FR-06 الوحدات التنظيمية** | `/app/units` | اختبار CRUD واختبار regression لرفض أب من معسكر آخر أو إحالة ذاتية/دورة/نقل معسكر غير متوافق | **API مغطى.** التحقق الهرمي مطبق في POST/PUT؛ الحذف متاح API فقط وغير ظاهر في واجهة الوحدات. |
| **FR-07 الرتب والمناصب** | `/app/ranks`, `/app/positions` | اختبار CRUD المرجعي، مع صلاحيات منفصلة لكل مورد | **API مغطى.** الواجهة تعرض الإضافة والتعديل؛ الحذف غير ظاهر في الشاشات الحالية. |
| **FR-08 التعيينات** | `/app/assignments` | اختبار التعيينات التاريخية الذرية، وإغلاق الحالي السابق؛ اختبار مستخدم يملك `assignments.manage` فقط | **API مغطى.** أضيف `GET /assignments/eligible-personnel` لإرجاع المعرّف والاسم فقط إلى مدير التعيينات، وأصبحت الواجهة تستخدمه بدل `personnel.manage`. |
| **FR-09 الانتقالات** | `/app/transfers` | اختبار نقل ذري وسعة ووحدة وجهة وطلبين متزامنين وRBAC وإشعارات النجاح/الرفض | **API مغطى.** النقل يُنفّذ مباشرة ويسجل `completed`؛ لا يوجد مسار موافقة منفصل أو طلب معلق. |
| **FR-10 المستخدمون** | `/app/users` | اختبار إنشاء/تحديث وعدم كشف تجزئة كلمة المرور، وحماية آخر مدير | **API مغطى.** التعطيل متاح، والحذف الفعلي للحساب غير متاح. لا اختبار متصفح شامل. |
| **FR-11 الأدوار والصلاحيات** | `/app/roles` | اختبار تطبيق تغييرات الصلاحيات فورًا وحماية آخر مدير ورفض RBAC | **API مغطى.** إدارة الأدوار تتطلب `users.manage`؛ لا اختبار متصفح لكل توليفات الدور. |
| **FR-12 لوحة التحكم** | `/app/dashboard` | `GET /reports/summary`؛ اختبار إيجابي يثبت المرشحات وتوزيع الحالة؛ اختبار RBAC | **API مغطى.** تعرض اللوحة الإجمالي والتوزيع حسب المعسكر والرتبة والحالة، مع فلاتر التقرير المشتركة. |
| **FR-13 التقارير والتصدير** | `/app/dashboard` | اختبار Excel/PDF ومرشحات التاريخ/المعسكر/الحالة وحفظ المرشحات في حدث التدقيق | **API والواجهة منفذان.** الفلاتر موضحة للمستخدم؛ الفترة تخص إنشاء سجل الفرد وتاريخ طلب النقل، والمعسكر/الحالة لقطة الأفراد الحالية. لا يوجد اختبار تنزيل متصفح آلي. |
| **FR-14 سجل التدقيق** | `/app/audit` | اختبار `from` و`to` معًا، التاريخ غير الصالح والمعكوس، وحدود المدير | **API مغطى.** أُصلح استبدال حد `from` بحد `to`. لا اختبار E2E لكل مرشحات الشاشة. |
| **FR-15 الإشعارات** | `/app/notifications` | اختبارات توليد إشعار للنقل والحالات الحساسة وتغييرات صلاحيات الدور؛ القراءة/التعليم للمستخدم الحالي | **API مغطى.** نطاق الأحداث الحالي أحداث نقل/حالة حساسة/تعديل صلاحيات. الإشعارات داخل التطبيق وليست دفعًا فوريًا خارج التطبيق. |
| **FR-16 إعدادات النظام** | `/app/settings` | `GET/PUT /settings` وقراءة policy؛ اختبار RBAC والتحقق والتدقيق وسياسة كلمات المرور ومدة JWT الجديدة | **منفذ ومختبر.** تغيير الإعدادات ذري؛ كلمة المرور الجديدة فقط تتأثر، والرموز النشطة لا تُبطل. لا اختبار E2E للشاشة. |
