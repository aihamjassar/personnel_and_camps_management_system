# سجل التدقيق (Audit Log) — Audit.md

> توثيق مخصّص لوحدة سجل التدقيق (FR-14) نظرًا لحساسيتها الأمنية العالية — يجمع كل ما ورد عنها متفرقًا في `Architecture.md` و`Flow-of-Event.md` و`Data-Flow.md` في مرجع واحد مركّز.

---

## 1. الغرض من الوحدة

توفير سجل تفصيلي وغير قابل للتعديل (Immutable) لكل عملية حسّاسة تحدث في النظام، بحيث يمكن دائمًا الإجابة على: **من فعل ماذا، متى، وعلى أي سجل؟**

---

## 2. جدول قاعدة البيانات المرتبط

| الحقل | النوع | الوصف |
|---|---|---|
| log_id | INTEGER (PK, AUTO_INCREMENT) | المعرّف الفريد للسجل |
| user_id | INTEGER (FK → Users) | من قام بالعملية |
| action_type | VARCHAR / ENUM | نوع العملية (إنشاء / تعديل / حذف / تسجيل دخول / تغيير صلاحية...) |
| target_table | VARCHAR | الجدول المتأثر (Personnel, Camps, Users...) |
| target_id | INTEGER | معرّف السجل المتأثر |
| old_value | JSON (nullable) | القيمة قبل التعديل |
| new_value | JSON (nullable) | القيمة بعد التعديل |
| ip_address | VARCHAR (nullable) | عنوان IP الذي صدر منه الطلب |
| created_at | TIMESTAMP (DEFAULT NOW) | الطابع الزمني للعملية |

**العلاقة:** `Users (1) ──< AuditLogs (N)` — كل مستخدم قد يُنشئ عدة سجلات تدقيق.

---

## 3. الأحداث الإلزامية التسجيل (من Flow-of-Event.md)

1. كل محاولة تسجيل دخول — ناجحة أو فاشلة (`UserLoginSucceeded` / `UserLoginFailed`).
2. كل إنشاء/تعديل/حذف لبيانات الأفراد أو المعسكرات أو الوحدات.
3. كل عملية انتقال فرد (`TransferRequested`, `TransferCompleted`, `TransferRejected`).
4. كل تغيير في حالة فرد (`PersonnelStatusChanged`).
5. كل تغيير في الأدوار أو الصلاحيات (`RoleOrPermissionChanged`) — حدث حسّاس بأولوية قصوى.
6. كل تعديل على إعدادات النظام العامة (`SystemSettingChanged`).
7. كل حظر مؤقت لحساب نتيجة تجاوز محاولات الدخول (`AccountLockedTemporarily`).
8. كل عملية استعادة من نسخة احتياطية.
9. كل استعراض لسجلات التدقيق نفسها (Meta-Audit) — لمنع إساءة استخدام هذه الشاشة ذاتها.

## 4. نقطة النهاية (API)

| الطريقة | المسار | الوصف | الصلاحية |
|---|---|---|---|
| GET | `/api/v1/audit` | استعراض السجلات مع دعم الفلترة (بالمستخدم / التاريخ / نوع العملية) | **مدير النظام فقط** |

**الاستجابة:** تُرجع قائمة مرتبة زمنيًا (الأحدث أولًا) بصيغة الاستجابة الموحّدة `{status, data, error}`.

---

## 5. آلية التسجيل التقنية (من Flow-of-Action.md)

- التسجيل يتم من **طبقة التكامل (Integration Layer)** وليس من طبقة العرض، لضمان عدم إمكانية تجاوزه من الواجهة الأمامية.
- في العمليات متعددة الجداول (كالانتقالات)، يُسجَّل الحدث **بعد نجاح المعاملة القاعدية (Transaction) بالكامل**، لتفادي تسجيل عمليات لم تكتمل فعليًا.
- السجلات **لا تُحدَّث ولا تُحذف أبدًا** بعد إنشائها (Append-Only) — أي تصحيح لاحق يُسجَّل كحدث جديد منفصل يشير للسجل الأصلي.

---

## 6. اعتبارات الأمان الخاصة بهذه الوحدة

| الجانب | التطبيق |
|---|---|
| الوصول | صلاحية "مدير النظام" حصرًا (لا استثناءات) |
| التخزين | نسخ احتياطي دوري ومشفّر لسجلات التدقيق تحديدًا |
| عدم القابلية للتعديل | لا توجد نقطة API لـ `PUT` أو `DELETE` على هذا الجدول إطلاقًا |
| الأداء | فهرسة (Index) على `user_id`, `created_at`, `target_table` لتسريع الفلترة |

