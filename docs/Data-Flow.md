# تدفق البيانات (Data Flow)

---

## 1. تدفق البيانات العام على مستوى النظام (من قسم 9.3 في دراسة الجدوى)

يرسل المستخدم طلبًا من الواجهة الأمامية إلى طبقة API، والتي تتحقق من رمز المصادقة (JWT) وصلاحيات الدور. يُمرَّر الطلب إلى طبقة منطق الأعمال المختصة، والتي تتفاعل عند الحاجة مع طبقة التكامل لتنسيق عمليات تشمل أكثر من وحدة، قبل أن تُخزَّن أو تُسترجَع البيانات من طبقة قاعدة البيانات، وتُعاد الاستجابة إلى المستخدم بتنسيق JSON موحّد.

```
┌──────────┐     JWT + Request      ┌──────────────┐
│  Client  │ ──────────────────────►│   API Layer   │
│ (React)  │                         │ (REST/JSON)   │
└──────────┘ ◄────────────────────── └──────┬────────┘
   status/data/error                        │
                                             ▼
                                   ┌───────────────────┐
                                   │  Business Logic    │
                                   │  (Validation+RBAC)  │
                                   └─────────┬───────────┘
                                             │
                              ┌──────────────┴───────────────┐
                              ▼                               ▼
                    ┌──────────────────┐            ┌──────────────────┐
                    │ Integration Layer │            │   (مباشر لوحدة    │
                    │ (تنسيق بين وحدات) │            │    واحدة فقط)     │
                    └─────────┬─────────┘            └─────────┬─────────┘
                              └───────────────┬──────────────────┘
                                              ▼
                                   ┌────────────────────┐
                                   │  Database Layer     │
                                   │   (PostgreSQL)       │
                                   └────────────────────┘
```

## 2. خريطة تدفق البيانات بين الجداول الرئيسية (مبنية على ER Diagram)

```
Camps (1) ──────< OrganizationalUnits (N)
                          │
                          │ (1)
                          ▼
                    Personnel (N) ───────► Ranks (1)
                    │      │
        ┌───────────┘      └───────────┐
        ▼                              ▼
  Assignments (N)                Transfers (N)
        │
        ▼
   Positions (1)

Personnel (1) ──────< PersonnelStatus (N)   [سجل تاريخي كامل]

Users (M) ───< UserRoles >─── Roles (M) ───< RolePermissions >─── Permissions (M)

Users (1) ──────< AuditLogs (N)   [كل عملية حسّاسة تُنشئ سجل تدقيق]

Users (1) ──────< Notifications (N)
```

**قراءة الخريطة:**
- معسكر واحد يحتوي عدة وحدات تنظيمية (One-to-Many).
- كل وحدة تضم عدة أفراد (One-to-Many).
- الفرد الواحد قد يملك أكثر من سجل تعيين تاريخيًا (One-to-Many).
- كل عملية انتقال للفرد تُنشئ سجلًا في `Transfers` دون حذف السجل السابق.
- حالة الفرد تُحفظ بشكل تراكمي (تاريخي) في `PersonnelStatus` وليس كتابة فوقية.
- المستخدمون والأدوار والصلاحيات ترتبط بعلاقات متعددة لمتعدد (Many-to-Many) عبر جداول ربط.

## 3. تدفق البيانات لكل وحدة وظيفية رئيسية

### أ) وحدة إدارة الأفراد
`Frontend (نموذج) → API /personnel → Business Logic (Validation) → Database (Personnel) → AuditLogs`

### ب) وحدة إدارة المعسكرات والوحدات
`Frontend → API /camps ، /units → Business Logic (تحقق من العلاقة الهرمية) → Database (Camps, OrganizationalUnits)`

### ج) وحدة الانتقالات (الأكثر تعقيدًا في تدفق البيانات)
`Frontend → API /transfers → Business Logic (تحقق من السعة) → Integration Layer (معاملة موحّدة عبر Personnel + Transfers + PersonnelStatus) → Database → AuditLogs → Notifications`

### د) وحدة التقارير
`Frontend (فلاتر) → API /reports/summary → Business Logic (استعلامات تجميعية JOIN/GROUP BY عبر عدة جداول) → توليد PDF/Excel → Frontend (تنزيل)`

### هـ) وحدة المصادقة والصلاحيات
`Frontend (بيانات دخول) → API /auth/login → Business Logic (bcrypt + JWT) → Database (Users, Roles, Permissions) → Frontend (تخزين الرمز في الذاكرة)`

## 4. تصنيف حساسية البيانات المتدفقة

| نوع البيانات | مستوى الحساسية | طبقة الحماية |
|---|---|---|
| كلمات المرور | حرج | bcrypt hash فقط، لا تُخزَّن كنص صريح أبدًا |
| رمز JWT | حرج | صلاحية زمنية محدودة، لا يُخزَّن في localStorage |
| بيانات الأفراد الشخصية | عالٍ | RBAC + تحقق من نطاق الصلاحية (وحدة/معسكر) |
| سجلات التدقيق | عالٍ | صلاحية "مدير النظام" فقط، غير قابلة للتعديل |
| بيانات التقارير المجمّعة | متوسط | صلاحية "عرض التقارير" |
| بيانات الإعدادات العامة | حرج | صلاحية "مدير النظام" فقط |

> **تذكير:** جميع البيانات المتداولة في هذا المشروع افتراضية بالكامل لأغراض أكاديمية — التصنيف أعلاه توضيحي لمحاكاة نظام حقيقي فقط.
